Codebase explanation for Hotel-Housekeeper

Scope note: This explains the authored project files and the local/generated folders that are visible in the working tree. It does not enumerate dependency internals under node_modules/, Next.js build internals under .next/, or Git internals under .git/.

Folders

./
The repository root is a Next.js App Router application backed by a local Supabase database. It holds app routes, shared UI, database helpers, Supabase migrations/configuration, tests, and package/tooling configuration.

.git/
This is Git's local repository metadata, including commit history, refs, index data, and hooks. It is not application code and normally should not be edited directly.

.next/
This is generated Next.js development/build output created by running the app. It is ignored by Git and can be deleted or regenerated by Next.js.

node_modules/
This is generated dependency output installed by pnpm. It is ignored by Git and should be recreated from package.json and pnpm-lock.yaml.

app/
This is the Next.js App Router directory containing pages, API route handlers, global CSS, and the root layout. URL structure maps directly to subfolders and page.tsx or route.ts files inside this directory.

app/api/
This folder contains server-only API route handlers. In this app, those handlers expose room data to the client.

app/api/rooms/
This API route group serves the authenticated user's room board data. Its default route uses the user's Supabase session and database RLS.

app/api/rooms/all/
This API route group serves the beta all-rooms endpoint. It uses the Supabase service role client, which bypasses normal user RLS and is intentionally important to the data-leak investigation task.

app/board/
This route group contains the authenticated room board page and its client polling wrapper. The server page fetches initial room data, and the client component periodically refreshes it.

app/login/
This route group contains the local-development email/password login page. It signs users into Supabase from the browser and then navigates to the board.

app/rooms-all/
This route group contains the beta "all rooms" page. It fetches from /api/rooms/all and renders a table of rooms across hotels.

components/
This folder contains reusable React UI components used by the app. It includes app-specific components like room cards and generated/design-system primitives.

components/ui/
This folder contains reusable low-level UI primitives based on Base UI, shadcn configuration, Tailwind classes, and lucide icons. These components provide common controls such as buttons, badges, cards, and dropdown menus.

lib/
This folder contains shared non-UI application utilities. It currently holds Supabase client factories, TypeScript database-facing types, and class name helpers.

lib/supabase/
This folder contains the three Supabase client constructors used by the app. The browser and server clients use the anon key and user session, while the service client uses the service role key for privileged server-only access.

lib/types/
This folder contains TypeScript types that model database rows and constrained values used by the UI. These types keep room status, room type, assignment, and staff shapes consistent across components.

public/
This folder contains static files served directly by Next.js. The current SVGs are starter/static icon assets and are not central to the room board business logic.

scripts/
This folder contains local utility scripts run from package.json. The seed script creates demo hotels, auth users, staff, and room assignments.

supabase/
This folder contains local Supabase CLI configuration and database migrations. It also has ignored runtime folders created by the Supabase CLI.

supabase/.branches/
This is generated local Supabase CLI branch metadata. It is ignored inside the Supabase folder and is not application logic.

supabase/.temp/
This is generated local Supabase CLI temporary state. It is ignored inside the Supabase folder and can be recreated by Supabase CLI commands.

supabase/migrations/
This folder contains ordered SQL migrations for the local Supabase database. The app's schema, RLS policies, triggers, and realtime publication setup live here.

supabase/snippets/
This folder is present but empty. It is likely available for local Supabase SQL snippets or future helper files.

tests/
This folder contains Vitest test setup and smoke tests. The current test verifies that Supabase RLS restricts a Hyatt user to Hyatt room assignments.

Root files

.DS_Store
This is a macOS Finder metadata file. It is not application code and is ignored by the root .gitignore pattern.

.env.local
This local-only environment file holds the Supabase URL, anon key, and service role key used by the running development app. It is ignored by Git and should not be committed or copied into documentation with its values.

.gitignore
This tells Git to ignore generated dependencies, macOS metadata, local environment secrets, and Next.js build output. It keeps node_modules/, .DS_Store, .env.local, and .next/ out of version control.

README.md
This is the project brief and setup guide for the take-home exercise. It describes the housekeeping board app, local Supabase setup, seeded credentials, required feature work, investigation options, and submission instructions.

components.json
This configures shadcn/ui generation conventions for the project. It selects the base-nova style, Tailwind CSS file, lucide icons, React Server Components, TSX, and import aliases such as @/components and @/lib.

eslint.config.mjs
This is the ESLint flat config. It extends Next.js core web vitals and TypeScript rules while ignoring generated output such as node_modules, .next, out, build, and next-env.d.ts.

next-env.d.ts
This is a generated Next.js TypeScript declaration shim. It brings Next.js and image types into the TypeScript program and should not be edited manually.

next.config.ts
This is the Next.js configuration file. It currently exports an empty config object, so the app runs with default Next.js behavior.

package.json
This defines the project package, scripts, dependencies, dev dependencies, and package manager. Important scripts include pnpm dev, pnpm build, pnpm lint, pnpm test, and pnpm seed.

pnpm-lock.yaml
This lockfile pins the exact dependency graph resolved by pnpm. It makes installs reproducible across machines and should be updated only through pnpm.

pnpm-workspace.yaml
This configures pnpm workspace/build behavior. It explicitly allows install/build scripts for sharp, unrs-resolver, esbuild, and msw.

postcss.config.mjs
This configures PostCSS to use the Tailwind CSS PostCSS plugin. Next.js uses it when compiling the global CSS and Tailwind utilities.

tsconfig.json
This is the TypeScript compiler configuration. It enables strict type checking, Next.js's TypeScript plugin, bundler-style module resolution, and the @/* path alias.

vitest.config.ts
This configures Vitest for the project. It uses the React plugin, loads tests/setup.ts, runs in the node environment, and maps @ to the repository root.

App files

app/.DS_Store
This is a macOS Finder metadata file inside the app folder. It is not application code and is ignored by the root .gitignore pattern.

app/favicon.ico
This is the browser favicon served by Next.js for the app. It is static branding/browser chrome metadata rather than app behavior.

app/globals.css
This is the global stylesheet for the app. It imports Tailwind, animation utilities, shadcn Tailwind styles, defines design tokens for light/dark themes, and applies base border/body/font styles.

app/layout.tsx
This is the root layout for all routes. It loads Geist fonts, sets the default page title, wraps children in the html/body shell, and mounts the Sonner toast provider.

app/page.tsx
This is the root home route. It checks the current Supabase user on the server and redirects signed-out users to /login or signed-in users to /board.

app/login/page.tsx
This is a client-side login page for local development. It pre-fills the Hyatt manager credentials, signs in with Supabase email/password auth, shows errors, and redirects to /board after success.

app/board/page.tsx
This is the authenticated board server page. It requires a Supabase session, fetches today's room assignments through the anon/RLS server client, and passes those rows into BoardClient.

app/board/board-client.tsx
This is the client-side wrapper for the room board grid. It renders room cards from initial server data and polls /api/rooms every 10 seconds to refresh room assignments.

app/rooms-all/page.tsx
This is the beta all-rooms client page. It fetches /api/rooms/all once on mount, records any error, and renders a table with hotel, room number, and status.

app/api/rooms/route.ts
This is the authenticated API endpoint for current-day room assignments. It rejects unauthenticated users, queries room_assignments through the session-aware Supabase client, and returns JSON.

app/api/rooms/all/route.ts
This is the beta all-rooms API endpoint. It uses the service role client to query current-day room assignments joined to hotels, bypassing user RLS and exposing cross-hotel data if called.

Component files

components/room-card.tsx
This renders a single housekeeping room card. It shows the room number, room type, status badge, optional VIP/DND/Pets flags, and optional remarks.

components/status-badge.tsx
This converts compact room status codes into human-readable labels. It renders the label inside the shared Badge component with the outline variant.

components/ui/badge.tsx
This defines a reusable Badge primitive using Base UI's render hook and class-variance-authority variants. It supports variants such as default, secondary, destructive, outline, ghost, and link.

components/ui/button.tsx
This defines the shared Button primitive on top of Base UI's button component. It centralizes Tailwind styling for variants, sizes, focus states, disabled states, and icon sizing.

components/ui/card.tsx
This defines composable Card primitives such as Card, CardHeader, CardTitle, CardDescription, CardAction, CardContent, and CardFooter. RoomCard uses these pieces to produce consistent card layout and styling.

components/ui/dropdown-menu.tsx
This defines a full dropdown menu component set on top of Base UI's menu primitives. It includes triggers, content, groups, labels, items, submenus, checkbox/radio items, separators, shortcuts, animations, and lucide check/chevron icons.

Library files

lib/.DS_Store
This is a macOS Finder metadata file inside the lib folder. It is not application code and is ignored by the root .gitignore pattern.

lib/supabase/client.ts
This creates the browser Supabase client. It uses NEXT_PUBLIC_SUPABASE_URL and NEXT_PUBLIC_SUPABASE_ANON_KEY so client-side code can authenticate and make RLS-scoped requests.

lib/supabase/server.ts
This creates the server-side Supabase client that is aware of Next.js cookies. It reads and writes auth cookies when possible, while safely no-oping writes from Server Components.

lib/supabase/service.ts
This creates a privileged Supabase service role client for server-only use. It disables session persistence/refresh and uses SUPABASE_SERVICE_ROLE_KEY, which bypasses normal RLS protections.

lib/types/database.ts
This defines hand-written TypeScript types for room statuses, room types, room assignments, and staff rows. These types are used by UI components to match expected database fields.

lib/utils.ts
This exports the cn helper for CSS class composition. It combines clsx with tailwind-merge so conditional class names can be merged without conflicting Tailwind utilities.

Script files

scripts/seed.ts
This script seeds local Supabase using the service role key from .env.local. It creates two demo hotels, four auth users, user-hotel links, staff rows, and 60 current-day room assignments, then prints login credentials.

Supabase files

supabase/.DS_Store
This is a macOS Finder metadata file inside the Supabase folder. It is not application code and is ignored by the root .gitignore pattern.

supabase/.gitignore
This ignore file is scoped to the Supabase folder. It ignores Supabase CLI branch/temp state and dotenvx/local env files that should not be committed.

supabase/config.toml
This is the local Supabase CLI configuration. It defines local service ports, exposed schemas, database version, auth behavior, Studio, email testing, storage, realtime, edge runtime, analytics, and other local dev service settings.

supabase/.branches/_current_branch
This generated Supabase CLI file records the current local branch context. It is ignored by supabase/.gitignore and is not application logic.

supabase/.temp/cli-latest
This generated Supabase CLI file stores temporary CLI state. It is ignored by supabase/.gitignore and can be recreated by Supabase commands.

supabase/migrations/20260101000000_init.sql
This migration creates the app database schema: hotels, user_hotels, staff, room_assignments, and board_activity_log. It enables RLS, adds per-hotel access policies, adds triggers for activity logging and updated_at maintenance, and publishes room/activity tables to Supabase Realtime.

Test files

tests/setup.ts
This Vitest setup file loads .env.local before tests run. That gives tests access to the local Supabase URL and anon key.

tests/rls.smoke.test.ts
This smoke test signs in as the Hyatt manager through the anon Supabase client and queries room assignments. It verifies RLS returns only Hyatt rows, giving quick coverage for tenant isolation.
